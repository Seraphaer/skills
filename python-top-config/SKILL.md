# Python 顶部配置开发

## 核心约定

用户通过修改脚本顶部的配置区调整运行参数，然后直接运行 `python script.py`。可调参数应集中、醒目、含义明确，不能散落在函数内部。

不使用 `argparse`、`parse_args()`、`sys.argv`、Click、Typer 或其他命令行参数解析方式。默认不增加 JSON、YAML、环境变量覆盖或交互输入等并行配置入口；用户明确要求的配置来源除外。

与架构优先开发技能一起使用时，继续遵循先架构、函数契约、完整骨架、逐个实现的流程；其中配置入口使用本技能的顶部 CONFIG 区，替换示例中的命令行配置和解析函数。

## 配置区设计

- 在模块说明和必要导入之后、业务函数之前设置醒目的 `# CONFIG：修改这里的参数` 区域。用户无需阅读业务代码就能找到配置。
- 小脚本优先使用少量有意义的大写常量；参数较多或需要组合传递时，使用简单的类型化 `Config` 和一个集中实例 `CONFIG`。不要强制所有脚本都使用配置类。
- 配置类只声明字段与类型，可调实际值统一写在 `CONFIG` 实例中，避免类默认值与实例值形成两处编辑入口。
- 对参数注明用途，以及必要的单位、范围、可选值和路径规则。参数分组按实际用途划分，如输入输出、处理参数和运行选项，不添加无用参数。
- 派生值由基础配置计算，避免同一信息需要改多处。算法内部不需要用户调整的实现常量不必放入配置区。
- 路径使用 `pathlib.Path`。默认将相对路径基准明确设为脚本目录，或遵循项目已有约定；在注释中说明，不能隐式依赖启动目录。
- 不在配置区执行文件读取、目录创建、网络请求等操作；这些操作放在运行入口之后。

## 函数与主流程

配置集中编辑不等于业务逻辑依赖全局状态。由 `main()` 读取顶部配置并校验，将必要参数显式传给功能函数；业务函数不直接读取或修改全局 CONFIG，也不为每个小函数传入无关的完整配置对象。

每个函数职责明确，使用类型标注和简短 docstring 说明输入、输出；必要时说明异常与副作用。将核心处理、输入输出和流程编排分开，避免一个函数承担全部工作。

在开始实际处理前校验会影响正确性的配置，例如正数要求、互斥选项、允许值、输入输出路径冲突。错误信息指出具体参数和原因，不能静默纠正配置或把失败伪装成成功。

独立脚本使用 `main()` 和 `if __name__ == "__main__":`，导入模块时不自动运行业务。配置对象在运行过程中保持稳定，不将中间结果写回配置。

## 配置与传参示例

以下示例演示配置布局与显式传参；实际脚本只保留任务需要的参数，并按目标业务组织函数。

```python
"""根据顶部配置缩放一组数值；直接运行本文件即可。"""

from dataclasses import dataclass


# ==================== CONFIG：修改这里的参数 ====================
@dataclass(frozen=True)
class Config:
    values: tuple[float, ...]
    scale: float


CONFIG = Config(
    values=(1.0, 2.0, 3.0),  # 待处理数值，允许为空
    scale=2.0,              # 缩放倍数，必须大于 0
)
# ==================== CONFIG END ====================


def validate_config(config: Config) -> None:
    """输入：运行配置；输出：None；scale 非正或为 NaN 时抛出 ValueError。"""
    if not config.scale > 0:
        raise ValueError("CONFIG.scale 必须大于 0")


def scale_values(values: tuple[float, ...], scale: float) -> list[float]:
    """输入：原始数值和倍数；输出：按原顺序缩放的列表，不修改输入。"""
    return [value * scale for value in values]


def main() -> None:
    """输入：顶部 CONFIG；输出：None；副作用：打印处理结果。"""
    validate_config(CONFIG)
    result = scale_values(CONFIG.values, CONFIG.scale)
    print(result)


if __name__ == "__main__":
    main()
```

## 修改现有脚本与交付

修改已有脚本时，保持本次目标范围和合理的函数结构；将目标脚本的运行参数及其有效默认值迁移到顶部配置，移除相应命令行解析和过时的运行说明。不要顺带改造无关脚本或整个项目。

交付前确认可调参数集中、注释准确、函数依赖明确，直接运行无需附加命令行参数。按任务风险验证正常配置和重要无效配置；涉及外部副作用时采用合适的隔离验证。

最终说明配置文件位置、需要修改的参数、直接运行方式及验证结果，不提供已经移除的命令行参数示例。
