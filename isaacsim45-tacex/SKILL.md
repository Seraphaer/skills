# Isaac Sim 4.5 与 TacEx 开发

严格遵守：**先阅读 → 再设计 → 再动手 → 验证**。没有完成相关资料阅读和设计，不开始修改代码。阅读与设计完成后自主继续实现，不把设计阶段变成例行等待用户批准。

## 1. 先阅读：建立可信依据

- 阅读项目约定、现有入口、配置、相关模块及调用方，理解当前代码的职责和数据流。先定位实际使用的运行环境、Isaac Sim 版本、Isaac Lab 版本（若涉及）及 TacEx checkout/提交；不要为了匹配示例擅自升级环境。
- **每次涉及 Isaac Sim API、生命周期或仿真行为，都必须查阅 Isaac Sim 4.5 对应的官方文档。每次涉及 TacEx API、配置或行为，都必须阅读当前使用版本的 TacEx 实现源码。跨两者的集成任务必须两边都查。** 不凭记忆、搜索摘要或未核实的示例直接写调用。
- Isaac Sim 官方文档入口：[4.5.0 文档](https://docs.isaacsim.omniverse.nvidia.com/4.5.0/index.html)。进入与任务相关的 API、教程或迁移说明，核实页面版本；`latest` 页面只能作为线索，不能作为 4.5 兼容性的依据。
- TacEx 上游：[DH-Ng/TacEx](https://github.com/DH-Ng/TacEx)。优先阅读本地 checkout 的 `README.md`、`docs/source/`、`source/` 和 `scripts/` 中相关实现与示例。核对类/函数定义、配置字段、调用方和实际更新路径，不能只看 README。远端源码必须对应本地版本或明确说明差异。
- 当前研究工作区可从 `software/TacEx` 查找源码，从 `software/IsaacLab` 查找相关依赖；这些是发现线索，使用前检查是否存在，不写成跨机器固定路径。若涉及 Isaac Lab，核对当前 checkout 的配置与实现，不照搬最新版示例。
- 阅读重点按任务选择：应用启动与 import 顺序、扩展启用、场景初始化与 reset、step/render/update 时序、传感器缓冲区、坐标系与单位、四元数顺序、张量 shape/device、物理后端与资源加载。对实际用到的行为逐一找到依据。
- 在设计说明中记录关键依据：官方文档链接和章节，或源码路径、符号与提交；说明确认了什么。区分已确认事实与待验证假设。
- 文档不可访问时，尝试匹配版本的官方离线文档；TacEx 本地缺失时，尝试匹配版本的上游源码。若关键行为仍无法核实，明确缺口，继续不依赖它的阅读和设计；不要编造接口，也不要把基于假设的实现宣称为兼容。

## 2. 再设计：明确职责与接口

修改前给出与任务规模相称的简短设计，包括：

- 目标行为、涉及的入口/模块以及需要保留的现有行为。
- 配置 → 应用/场景 → 物理与传感器更新 → 数据处理/输出的数据流，以及各模块的职责。
- 主要函数或类的输入输出；涉及仿真数据时明确单位、坐标系、shape、device 和更新时机。
- 是否需要重构、调整的边界，以及验证方法。

小改动可以用几句话完成，不为简单任务增加无用层级。复杂任务先确定模块边界与代码骨架，再逐块实现；设计必须依据阅读结果，而不是先猜架构再找文档背书。

## 3. 再动手：可读、易用，必要时重构

- 如果相关代码职责混杂、重复明显、入口难以理解、配置散落或补丁互相牵制，**必须先在当前任务涉及的范围内重构**，把控制流和职责理顺，再实现功能。重构应改善具体问题，不借机重写无关模块或更改物理语义。
- 分开配置、场景/传感器构建、仿真循环与数据处理；按复杂度使用清晰函数或模块，不强制每种职责都建文件。
- 使用表达物理含义的命名；函数职责单一、输入输出明确；减少重复、隐式全局状态、过深嵌套和不必要抽象。对外接口与关键数据结构补充必要类型标注。
- 将用户经常调整的参数集中到明显的配置入口，注明单位、用途和必要约束。项目已有配置体系时沿用；独立 Python 脚本默认使用顶部 `CONFIG`，通过编辑配置直接运行，不新增命令行参数解析，除非用户明确要求。
- 提供清晰的运行入口和可用的默认配置。资源路径不要依赖偶然的当前工作目录；必要的启动检查给出具体、可操作的错误信息。
- 注释解释设计原因、物理约定和非显然的时序约束，避免逐行翻译代码。不要用宽泛异常捕获、静默忽略或返回伪造数据掩盖问题。
- 对框架初始化、扩展加载、reset 与资源释放，沿用已核实的官方或源码模式。不得为“代码整洁”破坏必需的应用启动/import 顺序或仿真更新时序。
- 删除此次修改产生的废弃路径、临时调试代码与重复实现；发现仍有调用方时先完成迁移，不随意删除依赖接口。

## 4. 验证与交付

- 使用项目实际的 Isaac Sim/TacEx 启动方式和环境进行验证。语法检查或普通 Python import 成功不能证明仿真兼容。
- 选择与改动匹配的最小有效验证：场景可初始化、相关 reset/step/update 路径可运行，输出的 shape/device/有限值符合约定。涉及图像或触觉输出时检查实际数据与必要渲染，不能以“进程启动了”作为功能通过。
- 重构时比较关键外部行为、配置含义和输出，确认没有无意改变任务语义。涉及 GPU、渲染或不可用资产时，如实说明无法验证的部分，不宣称已通过。
- 交付简要说明修改内容、设计或重构理由、查阅的官方文档/源码依据、实际验证结果与剩余限制，并提供必要的运行方式和配置入口。
